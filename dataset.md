# Dataset and Reproducibility

## 1. External Data

None of the datasets below are included in this repository. They must be downloaded
separately and placed under `data/` as expected by the corresponding config files.

### KITTI — training data

Used to fine-tune YOLO26. Ultralytics-provided, YOLO-format conversion of the KITTI
object detection benchmark (images + YOLO-format labels).

- Download: https://github.com/ultralytics/assets/releases/download/v0.0.0/kitti.zip
- Expected layout / class list: see `data/kitti/kitti.yaml`.

### KITTI — object distance annotations

Used to obtain each object's real distance to the camera (for the distance-based
stratification of the results). This is a separate download from the training data
above: it is KITTI's official raw label format (`data_object_label_2`), which includes
the 3D location fields (including depth/distance) that are not present in the
Ultralytics YOLO-format conversion.

- Download: (https://www.cvlibs.net/datasets/kitti/eval_object.php?obj_benchmark=3d)
- Expected layout: `data/data_object_label_2/training/label_2/<image_id>.txt`, one line
  per ground-truth object; column 14 is the real distance `z` (meters) from the
  object's 3D location in camera coordinates.

### LOCO (Logistics Objects in COntext)

Used for the industrial use-case extension (5 classes: pallet, small load carrier,
stillage, forklift, pallet truck).

- Download: https://github.com/tum-fml/loco
- Official train/val split used: train = subsets {2, 3, 5}, val = subsets {1, 4}
  (warehouse/session-based split, not a random split).

## 2. Data Generated During This Work

This project's own pipeline produces two kinds of output: per-object saliency
heatmaps (`.npz`) and per-object CSV records. Only a couple of example heatmaps are
included in this repository, as illustration; everything else is regenerated by
running the pipeline.

### Heatmaps (`.npz`)

Two example files are included, one per method, both for the same KITTI validation
image (`000106`) so they can be compared directly:

- `results/examples/dcrisp_000106.npz` (D-CRISP)
- `results/examples/ssgradcampp_000106.npz` (SSGrad-CAM++)

Each `.npz` file stores one heatmap per detected object in the image, saved with
`numpy.savez_compressed` under the keys `obj_0`, `obj_1`, ... (one per object index);
each value is a 2D `float32` array at the model's letterboxed input resolution (not
rescaled back to the original image size).

### CSVs

Two main CSV types are produced:

- `object_level.csv`: one row per detected object, recording the detection itself
  (predicted class, confidence, bounding box) and how it matches against the KITTI
  ground truth.
- `eval_metrics.csv`: one row per object, recording the explainability evaluation
  metrics (localization, faithfulness and robustness/stability) computed from that
  object's heatmap.

### Reproducibility

All the CSV files and heatmaps described above are fully reproducible by running this
project's own scripts, using the parameter values documented in the thesis
